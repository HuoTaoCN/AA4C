# V0.7「Trust / Reach」真机验证清单

V0.7 的四个里程碑（R1 IPv6 双栈 / R2 信任传递 / R3 UPnP 端口映射 / R4 内置服务器）代码已全部
实现，自动化测试也都绿了——但**自动化测试证明不了这四件事真正要证明的东西**：

| 里程碑 | 自动化测试验到哪 | 验不到的部分（本文档要做的） |
|---|---|---|
| R1 | IPv6 **回环**（`[::1]`）跑通配对+传输；`[::]` 仍接受 IPv4 | 两台在**不同网络**、各自拿公网 IPv6 的设备能否直连 |
| R2 | 三节点引荐闭环（回环内） | 真实的「家 / 单位」两个局域网场景 |
| R3 | 编排逻辑（假后端） | **一次真实的 UPnP 交互都没发生过** |
| R4 | 内置服务器在回环上当汇合点 | 跨网可达（要 DDNS + 端口放行） |

> **为什么自动化测试里没有这些**：R3 的真实实现会**改跑测试那台机器所在路由器的配置**，
> 把它写进测试等于每次跑测试都在开发者家里开一个真端口，这是不可接受的（代码里有
> `CoreConfig::disable_port_mapping` 从结构上堵死这条路）。R1/R4 的跨网部分则需要两个真实的
> 不同网络，本环境不具备。

**验证顺序是有讲究的**：A 组只要一台机器，B 组要同一局域网两台，C 组才需要两个不同网络。
前面的过不了，后面的一定过不了——**按顺序做，卡住就停下来告诉我卡在第几条**。

## 0. 准备

### 0.1 怎么看日志

从终端启动才能看到日志（图标双击启动看不到）：

```bash
cd apps/desktop && RUST_LOG=info,aa4c_core=debug,aa4c_transfer=debug,aa4c_server=debug pnpm tauri dev
```

下面凡是写「日志里应出现」的，都是**真实存在于代码里的字符串**，可以直接 grep。

### 0.2 一台机器上跑两个实例（A 组会用到）

```bash
AA4C_DATA_DIR=/tmp/aa4c-a AA4C_DEVICE_NAME=实例A pnpm tauri dev
```

另开一个终端：

```bash
AA4C_DATA_DIR=/tmp/aa4c-b AA4C_DEVICE_NAME=实例B pnpm tauri dev
```

两个实例数据目录隔离，互相当成两台设备。

### 0.3 记录环境（出问题时这些信息最有用）

先把这几项记下来：

- 每台设备的操作系统与版本
- 路由器型号，以及管理界面里 **UPnP 是否开启**
- 本机是否有公网 IPv6：`curl -6 https://ifconfig.co` （返回地址 = 有；报错 = 没有）
- 本机公网 IPv4 是不是运营商级 NAT：`curl -4 https://ifconfig.co` 得到的地址，如果落在
  `100.64.0.0/10` 就是 CGNAT，**R3 的端口映射对你没用**（映射的是内网路由器，外面还有一层）

## A 组 · 单机（不需要第二台设备）

### A1 · 双栈监听真的绑上了 〔R1〕

启动后日志应出现 `transfer listener started` 与 `quic listener started`。然后：

```bash
lsof -nP -iTCP:42420 -sTCP:LISTEN
lsof -nP -iUDP:42420
```

- [ ] **通过条件**：TYPE 列是 **IPv6**、地址列是通配（`*:42420`），而不是 `127.0.0.1:42420`
- [ ] 日志里**没有** `dual-stack bind unavailable, falling back to IPv4-only`
      （出现这条说明回落到了纯 IPv4，请把整行贴给我）

> lsof 的输出格式各平台略有差异，看不太准也没关系——**A2 才是硬判据**，它测的是行为而不是
> 输出文本。

### A2 · 同一个监听器同时收 IPv4 与 IPv6 〔R1〕

```bash
nc -vz 127.0.0.1 42420
nc -vz ::1 42420
```

- [ ] **通过条件**：两条都显示 succeeded。**只要有一条失败，A2 就算没过**——这正是
      `IPV6_V6ONLY` 没被正确关掉时会出现的症状

### A3 · 内置服务器能起能停 〔R4〕

设置 → 远程连接 → 「让这台设备当中转站」打开 → 保存。

- [ ] 日志出现 `embedded server started`，且 `reflect endpoint listening`
- [ ] 界面**立即**（不是等半分钟）显示出一条 `aa4c://...` 地址
- [ ] `lsof -nP -iTCP:42421 -sTCP:LISTEN` 有结果
- [ ] **身份复用**：日志里这两行的指纹应当一致——
      - 启动时的 `AA4C core started`，字段 `id=<64 位十六进制>`
      - 打开开关后的 `aa4c-server listening`，字段 `device_id=<64 位十六进制>`

      两者来自**不同的代码路径**（Core 自己的身份 vs 内置服务器独立走一次
      `Identity::load_or_generate`），所以对得上才真能说明「没有凭空多出第二个身份」。
      界面上那条 `aa4c://...#` 后面的 16 位，应当是它的前缀。
- [ ] 关掉开关并保存 → 日志出现 `stopping embedded server`，且上面那条 `lsof` **不再有结果**

### A4 · 端口冲突的提示 〔R4〕

把内置服务器端口改成 42420（与传输端口相同）。

- [ ] 界面给出「不能和传输端口用同一个号」的提示
- [ ] 若强行保存：日志出现 `embedded server failed to start`，且**应用其余功能一切正常**
      （这一条是在验「失败不致命」）

### A5 · UPnP 端口映射 〔R3〕— **本组最关键的一条**

前置：`enable_remote` 要打开（映射的外层闸），且路由器 UPnP 已开启。

设置 → 远程连接 → 填一个服务器地址 → 打开「开启远程连接」→ 确认「自动在路由器上开端口」
是打开的 → 保存，**然后等最多 1 分钟**。

- [ ] 日志出现 `port mapping established`，带 `external=<公网IP>:<端口>`
- [ ] **去路由器管理界面看**（通常在「转发规则 / UPnP」页）：应有两条名为 **AA4C** 的映射，
      一条 TCP 一条 UDP，内部端口都是 42420
- [ ] 从**外网**验证端口真的通了（用手机 4G/5G 热点以外的网络，或在线端口检测工具）
- [ ] **退出应用** → 回路由器界面看，那两条 AA4C 映射**应当消失**
      （这一条验的是「不在你路由器上留洞」，很重要）

**如果日志里没有 `port mapping established`**：把 `RUST_LOG` 里加上 `igd_next=debug` 重跑，
把出现 `port mapping unavailable` 那几行贴给我——路由器不支持 UPnP 是常见情况，不算 bug，
但我需要知道是哪一步失败的。

## B 组 · 同一局域网两台设备

### B1 · 基础配对与传输没被 V0.7 弄坏 〔回归〕

- [ ] 两台设备互相发现、配对、双向发文件成功
- [ ] 传输卡片显示「**直连**」而不是「中继（较慢）」

> 这一条是回归检查。V0.7 动了全链路的监听绑定（`0.0.0.0` → `[::]`），**如果这里就出问题，
> 后面都不用测了，直接告诉我。**

### B2 · 信任传递 / 引荐 〔R2〕

需要三台设备（手机 + 两台电脑最典型）。若只有两台，可用 0.2 的方法在其中一台上跑两个实例。

设 P = 手机，H = 电脑1，W = 电脑2。

1. P 与 H 配对，**双方都在设置里把对方标记为「我的设备」**（引荐只在完全信任之间发生）
2. P 与 W 配对，同样双方互标「我的设备」
3. H 与 W **之间不做任何配对**

- [ ] 等最多 5 分钟（引荐周期），H 的「设置 → 已配对设备」顶部出现「**待确认的设备**」，
      里面是 W
- [ ] 文案里写明了**是谁说的**（应显示「你的『<P 的设备名>』说这也是你的设备」）
- [ ] **在点确认之前**：W 在 H 这里不是已配对设备（引荐本身不产生任何信任）
- [ ] H 点「标记为我的设备」，W 上也对 H 做同样操作
- [ ] 此后 H 与 W **从未配过对，却能互相看到对方的共享文件 / 互发文件**

单独验一下「忽略」：

- [ ] 在 W 上对 H 的引荐点「忽略」→ 该条消失，**且等一个引荐周期后不会再出现**
      （这一条验的是不会「删了又被加回来」）

### B3 · 局域网内经内置服务器互认 〔R4〕

用 A3 打开的内置服务器：

- [ ] 在另一台设备的「设置 → 远程连接 → 自建服务器地址」里填入 A3 那条 `aa4c://...`
      （局域网内先把地址里的主机名换成这台机器的局域网 IP）
- [ ] 打开「开启远程连接」，保存
- [ ] 两台设备仍能正常互传

## C 组 · 两个不同的网络（V0.7 真正要证明的东西）

> 这一组才是 V0.7 的意义所在。**做之前先确认 0.3 记录的信息**：如果两台设备都没有公网 IPv6、
> 且 IPv4 都在 CGNAT 后面，那么除非有一台在公网上（VPS 或有公网 IP 的家宽），否则连不通是
> **预期结果**而不是 bug——这正是 TRUST_DESIGN §2.2 说的「零第三方做不到 NAT 穿透」。

场景：设备甲在家（或家里网络），设备乙用手机热点 / 公司网络 / 另一处宽带。

### C1 · 跨网连通（走内置服务器当汇合点）〔R4 + R1/R3〕

1. 家里那台常开设备打开内置服务器（A3）
2. 给家里宽带配一个 **DDNS 域名**，指向家里的公网地址
3. 在设置里把那个域名填进「别人用什么地址找到这台设备」
4. 路由器上放行内置服务器端口（42421 的 TCP + UDP）——若 A5 的 UPnP 生效，这步可能已自动完成
5. 两台设备的「自建服务器地址」都填成界面给出的那条 `aa4c://<你的域名>:42421#<指纹>`

- [ ] 界面上的地址来源标注变成「**用的是你填的地址，只要它一直指向这台设备就长期有效**」
      （即 `reach = Configured`）
- [ ] 甲乙两台设备**在不同网络下**仍能互相看到、互发文件

### C2 · 有没有真的走到「直连」〔R1/R3 的实际收益〕

C1 通了之后，看传输卡片：

- [ ] 显示「**直连**」→ **R1/R3 生效了**，跳过了中继（这是最好的结果）
- [ ] 显示「中继（较慢）」→ 能用，但没吃到 R1/R3 的好处

如果是「中继」，帮我记录这几项，我据此判断是哪一档没打通：

- 两台设备各自 `curl -6 https://ifconfig.co` 的结果（有没有公网 IPv6）
- 两台设备各自 `curl -4 https://ifconfig.co` 的结果（是不是 CGNAT）
- A5 里 `port mapping established` 有没有出现过

### C3 · 跨网引荐 〔R2 的真实场景〕

这是 R2 存在的理由本身：家里的电脑和单位的电脑永远不会同处一网。

- [ ] 按 B2 的步骤，但 H 与 W **真的分处两个网络**
- [ ] 手机分别在两处与它们配对后，H 与 W 各自收到对方的「待确认」并确认成功
- [ ] **全程没有把任何一台电脑搬到另一个网络**

## 出问题时给我什么

按重要性排序，有多少给多少：

1. **卡在第几条**（例如「A5 第 2 项」）
2. 相关日志行（`RUST_LOG=debug` 下的原文，别改写）
3. 0.3 里记的环境信息
4. 路由器管理界面的截图（涉及 A5 / C1 时）

**明确不算 bug 的情况**（这些是设计上就这样，不用报）：

- 路由器不支持 UPnP → A5 过不了。日志会是 debug 级的 `port mapping unavailable`，不是错误
- 两边都在 CGNAT 后面且没有公网中转 → C 组连不通
- 内置服务器没填 DDNS 时地址标注为「只找到局域网地址」→ 这是**如实告知**，不是缺陷
- 引荐要等最多 5 分钟才出现 → 周期是刻意放慢的（设备列表几乎不变，没必要每 30 秒去问一次）
