## 1. 安装

从 [Releases](https://github.com/HuoTaoCN/AA4C/releases) 下载对应平台的安装包。

| 平台 | 文件 | 安装说明 |
|------|------|----------|
| Windows | `.msi` | 双击安装。首次运行会弹出防火墙询问，**必须勾选「专用网络」**，否则设备之间发现不到 |
| macOS | `.dmg` | 拖进「应用程序」。安装包**未做苹果签名**，首次打开需右键点图标 →「打开」→ 再点「打开」；或到「系统设置 → 隐私与安全性」里点「仍要打开」 |
| Linux | `.deb` / `.rpm` / `.AppImage` | deb/rpm 用系统包管理器安装；AppImage 执行 `chmod +x AA4C*.AppImage` 后直接运行 |
| Android | `.apk` | 实验版。需要在系统设置里允许「安装未知来源应用」 |

安装包由 GitHub Actions 在公开的 CI 流水线上构建，构建脚本在仓库里，任何人都可以自己复现或从源码构建。

## 2. 第一次使用：配对两台设备

配对是一次性的动作，配对之后设备会互相记住。

**准备**：两台设备连到**同一个 WiFi / 局域网**，都打开 AA4C。

1. **互相发现**。在首页的「附近设备」里，几秒内应该能看到对方的设备名。看不到就跳到 [FAQ 的发现问题](FAQ.md#找不到设备)。
2. **发起配对**。点对方卡片上的「配对」。
3. **核对确认码**。两台设备的屏幕上会各自显示一个 **6 位数字**。

   > ⚠️ **请务必用眼睛核对两边的数字是否完全一致**。这一步是 AA4C 唯一的安全关卡：这 6 位数字由两台设备各自独立算出、**从不经过网络传输**，中间人无法让两边显示成一样的数字。数字不一致就说明有人在中间捣鬼，**点拒绝**。

4. **两边都点确认**。配对完成。
5. **是不是你自己的设备？** 配对成功的弹窗会问一句。
   - 选**「是，我的设备」** → 该设备升级为**完全信任**，可以参与跨设备文件索引与同步。
   - 选**否**（或直接关掉） → 停留在**朋友**级别，只能收发文件与手动分享，不参与同步。

   这个选择随时可以在「设置 → 已配对设备」里改。

### 信任分级说明

AA4C 不是"配对了就把全部文件交出去"，信任分四级：

| 层级 | 给谁用 | 能索引/同步你的文件 | 收你发的文件 |
|------|--------|---------------------|--------------|
| **完全信任** | 你自己的多台设备 | ✅ 双向 | 可开启免确认 |
| **朋友** | 朋友 / 家人 / 同事 | ❌ 只能手动分享 | 需要你确认 |
| **临时** | 只打一次交道的设备 | ❌ | 每次都要确认 |
| **陌生** | 发现了但没配对 | ❌ | 直接拒收 |

**配对默认是「朋友」**，最小权限。只有你亲手升级过的设备才会看到你的同步文件索引。

## 4. 传输：把文件 AA 过去

**「传输」页 → 1 选文件 → 2 选设备 → 点 AA。**

### 选文件

- 把文件或文件夹**直接拖进虚线框**
- 或点「选择文件」/「选择文件夹」

支持任意类型、任意大小，文件夹会保持目录结构完整送达。

### 选设备

下方列出当前在线的已配对设备。没有设备说明对方不在线、不在同一网络，或还没配对。

### 对方会看到什么

- 默认：对方弹出接收确认框，**同意后才开始传**
- 如果对方是**完全信任**设备，并且在设置里打开了「信任设备来的文件自动接收」，则直接开始接收，不打扰

### 传输过程

- 底部任务条实时显示进度与速度，可随时取消
- 每个文件传完会做 **BLAKE3 完整性校验**，校验不过会自动重传
- 网络中断后重连会**从断点续传**，不用从头再来
- 收到的文件默认存在「设置 → 接收文件保存到」指定的目录（默认 `~/Downloads/AA4C`）

> 全程 TLS 1.3 加密，且加密没有关闭开关。

## 5. 同步：让文件夹在多设备之间保持一致

同步的对象是**完全信任的设备**——也就是你自己的多台设备。朋友级设备看不到同步索引。

### 添加同步文件夹

「同步」页 → 「+ 添加同步文件夹」 → 选一个目录。

添加后 AA4C 会：
1. 扫描该目录，建立本地索引（记文件名、大小、哈希，**不复制内容**）
2. 监听目录变化，文件增删改自动更新索引
3. 与在线的完全信任设备交换索引

> 「收到的」（Inbox，即接收目录）**自动纳入同步，不用手动添加**——在 A 上收到的文件，在 B 上也能取。

### 理解三种颜色

这是 AA4C 同步与传统同步工具最大的不同：**默认只同步"有哪些文件"，不同步内容**。

| 标记 | 含义 | 你能做什么 |
|------|------|------------|
| 🟢 **本地有** | 内容已在本机 | 直接打开 |
| 🟡 **可下载** | 内容在某台在线设备上 | **点一下就取回本机**，取完变绿 |
| 🔴 **设备离线** | 只有离线设备有这个文件 | 等那台设备上线 |

这样做的好处：NAS 上 1 TB 的素材库可以完整地"出现"在笔记本上，只占几 MB 的索引；真正需要哪个文件，点一下再拉。

### 冲突处理

两台设备上出现同名但内容不同的文件时，AA4C **不会替你选一个覆盖另一个**。该文件在列表里标记为「多版本」，各版本按序号并列显示，你可以分别取回后自己决定。

### 手动刷新

- 「刷新设备」：重新与在线设备交换索引
- 重新扫描：重建本机索引（一般不需要，文件监听是自动的）

## 6. 分享：把文件给好友、家人、同事

「分享」是给**指定的人**的，不是公开发布——AA4C 没有社区、没有资源广场。

### 生成分享链接

「分享」页 → 选一个文件 → 选有效期 → 「生成分享链接」。

| 有效期选项 | 说明 |
|------------|------|
| 1 小时后过期 | 临时给一下 |
| 1 天后过期 | |
| 7 天后过期 | 默认 |
| 长期有效 | 直到你手动撤销 |

> 只能分享**已在同步文件夹里的文件**。如果下拉框是空的，先去「同步」页添加一个同步文件夹。

生成后点「复制」，把 `aa4c://share/…` 链接发给对方（微信、邮件、随便什么方式）。

### 打开别人的分享

「分享」页下方的输入框，粘贴 `aa4c://share/…` 点打开即可。

### 分享的边界（重要）

- 链接**只对这一个文件有效**，不会连带暴露同目录其他文件
- **随时可撤销**：在「我的分享」里点撤销，链接立刻失效
- 可以看到「访问记录」，知道谁在什么时候取过
- 分享**不等于配对**，也不会把对方变成信任设备
- 走广域网需要先配置好自建服务器并打开远程连接（见 [自建服务器指南](SELF_HOSTING.md)）；同一局域网内则直接可用

## 7. 下载：统一下载中心

「下载」页支持两类链接，用同一个任务列表管理：

| 类型 | 例子 | 引擎 |
|------|------|------|
| 直链 | `https://…`、`http://…`、`ftp://…` | aria2 |
| BT / 磁力 | `magnet:?xt=urn:btih:…` | Transmission |

### 添加任务

点「添加下载」，把链接粘进去。**一行一个可以批量添加**——AA4C 会自动识别哪几行像是链接。

### 管理任务

- 单任务：暂停 / 继续 / 重试 / 取消（取消时可选择是否同时删除已下载的文件）
- 批量：全部暂停 / 全部继续 / 清除已完成
- 顶部有状态分栏（全部 / 进行中 / 已完成 / 出错）和搜索框

### 下载完成之后

如果「设置 → 归档 → 下载完成后自动归档」是开的，**并且**你至少启用了一条归档规则，文件会按规则自动分类移动（见下一节）。默认没有启用任何规则，所以默认行为是"就放在下载目录里"。

### 关于下载引擎

aria2 和 Transmission 是 GPL 软件。AA4C **不复制它们的代码**，而是把它们作为独立子进程运行，只通过 **127.0.0.1 回环地址 + 每次启动重新生成的随机密钥**通信。它们不监听局域网，别的机器连不上。

直链引擎（aria2）崩溃时，AA4C 会先尝试重连、再尝试完整重新拉起子进程，避免下载能力静默失效。如果重新拉起也失败，本次会话内下载会不可用——重启应用即可恢复。

> ⚠️ **使用者责任**：AA4C 只是下载工具，不提供、不索引、不推荐任何资源。请遵守所在地区的法律，只下载你有权下载的内容。

## 8. 归档与 AI：自动整理、模型库、知识库

「归档」页有四块内容。**核心原则：规则自动、AI 建议——只有确定性规则可以自动移动文件，AI 的输出永远只是待你确认的建议。**

### 8.1 归档规则（不需要 AI 也完整可用）

规则引擎是纯确定性的，不依赖任何模型。

**内置类别**（固定 11 种，不可增删；标签才是你自由发挥的维度）：

`模型 / 图片 / 视频 / 音频 / 文档 / 电子书 / 压缩包 / 安装包 / 代码 / 字幕 / 其他`

识别方式：扩展名表为主 + 文件头魔数（magic bytes）兜底，两者冲突时**以文件头为准**——所以改过扩展名的文件也认得出来。

**新建规则**：点「+ 新建规则」，填：

| 字段 | 说明 |
|------|------|
| 规则名称 | 自己看的 |
| 匹配类别 | 选一个或多个内置类别 |
| 目标目录模板 | 归档到哪里，相对归档根目录 |
| 标签 | 逗号分隔，可留空 |

> **规则默认是停用的**。这是有意的保守设计——自动移动文件是有风险的操作，必须由你明确启用。

**触发时机**：下载完成后（前提是「设置 → 下载完成后自动归档」开着），也可以在归档页手动对选中的文件执行。

### 8.2 撤销

「最近动作」列出最近的归档操作，每条都可以**一键撤销**，文件回到原来的位置。自动化必须可逆。

### 8.3 模型库

AA4C 会**解析 GGUF 文件头**来认识本地模型——只读文件开头的几十 KB，**永远不会读张量数据**，所以几十 GB 的模型也是瞬间完成。解析出：

- 模型架构（`general.architecture`）
- 模型名与参数规模（如 4B）
- 量化等级（如 Q4_K_M、Q8_0）
- 上下文长度

模型文件目录在「设置 → AI → 模型文件目录」配置，默认就是归档规则里「模型」类别的目标目录——**下载 GGUF → 自动归档进模型目录 → 模型库立刻可见**。

### 8.4 启用 AI 能力

AI 是**可选的**。不配置模型，归档规则照常工作，只是没有 AI 建议和知识库。

启用步骤：

1. 自己准备 GGUF 模型文件（从 Hugging Face 等处下载，AA4C 不代为分发模型）
   - **对话模型**：用于分类/标签建议和知识库问答
   - **嵌入模型**：知识库检索需要（仅做标签建议可以不配）
2. 放进模型文件目录
3. 「设置 → AI」里选定对话模型与嵌入模型

关于运行方式：

- 模型跑在本机的 `llama-server` 上，**零云端调用**，断网可用
- 引擎**懒启动**：用到才起，不用不占内存
- **空闲自停**：默认空闲 10 分钟后自动退出释放内存（可在设置里改）
- 同样绑定 127.0.0.1 + 随机密钥，不对外暴露

### 8.5 AI 标签 / 分类建议

选中文件让 AI 给建议，结果进入待确认列表，每条你可以**采纳**或**忽略**。

> **在你点「采纳」之前，AA4C 不会因为 AI 的判断移动任何文件。** AI 猜错的最坏后果，只是一条你忽略掉的建议。

### 8.6 本地知识库

对自己的文件提问。

1. 「知识库」区 → 添加一个目录作为来源，AA4C 扫描其中的文本 / 代码文件并在本地建索引
2. 输入问题 → 得到答案，**答案会附上原文引用**，方便你核实来源
3. 来源目录内容变了可以重新索引；不想要的来源可以删除

全过程在本机完成：文档不上传、不出网、不进任何云服务。

## 9. 记录

「记录」页是完整的传输历史，按时间分组：什么时候、和谁、传了几个文件、多大、成功还是失败（失败会带上原因）。

每条记录上还有两个快捷操作：

- 接收成功的：**打开所在文件夹**
- 发送失败的：**重新发送**（跳回「传输」页重新选一次）

## 10. 设置详解

### 基本

| 项 | 说明 |
|----|------|
| 设备名称 | 别人在「附近设备」里看到的名字，默认取主机名 |
| 接收文件保存到 | 收到的文件存哪里，默认 `~/Downloads/AA4C`。这个目录会自动纳入同步索引 |
| 信任设备来的文件自动接收 | 打开后，**完全信任**设备发来的文件不再逐次弹窗确认。默认关闭 |

### 远程连接

| 项 | 说明 |
|----|------|
| 自建服务器地址 | 形如 `aa4c://主机:端口#指纹`，指向你自己部署的 `aa4c-server` |
| 开启远程连接 | **默认关闭**。关着的时候 AA4C 完全不出网，只在局域网活动。必须先填服务器地址才能打开这个开关 |

部署方法见 [自建服务器指南](SELF_HOSTING.md)。

### 下载

> ⚠️ 下载相关设置**需要重启应用后生效**——它们会写进引擎启动时生成的配置文件，不做热更新。

| 项 | 说明 |
|----|------|
| 下载目录 | 默认系统下载目录。**必须在「接收文件保存到」目录之外**——放进去会被自动索引并分享给所有完全信任设备 |
| 下载限速（KB/s） | 留空 = 不限速 |
| 同时下载数 | 留空 = 用引擎默认值（aria2 是 5） |
| 单文件最大连接数 | 分段下载加速，即别的下载器说的"多线程下载"，1–16。留空时用一个合理的默认值（5），不是 aria2 自己的默认值 1 |
| BT 分享率上限 | 做种到这个分享率就停，留空 = 不限 |
| BT 空闲做种超时（分钟） | 多久没有上传活动就停止做种，留空 = 不限 |

### 归档

| 项 | 说明 |
|----|------|
| 归档根目录 | 默认文档目录下的 `AA4C归档`。必须与接收目录、下载目录互不嵌套 |
| 下载完成后自动归档 | 总开关，默认开启。但**每条规则自己默认是停用的**，所以不启用规则就不会有任何自动移动 |

### AI

| 项 | 说明 |
|----|------|
| 模型文件目录 | 默认 `<归档根>/模型` |
| 对话模型 / 嵌入模型 | 从模型目录里选，不选则 AI 能力不可用 |
| 空闲多久后自动释放内存（分钟） | 默认 10 |

### 已配对设备

列出所有已配对设备，可以：
- 调整信任级别（朋友 ↔ 完全信任）
- **解除配对**：对方立刻失去连接你的权限

## 11. 数据存在哪里

AA4C 不做任何隐藏存储，你的东西始终是普通文件：

| 内容 | 位置 |
|------|------|
| 收到的文件 | 「接收文件保存到」目录，就是普通文件，不加壳不加密封装 |
| 下载的文件 | 下载目录 |
| 归档的文件 | 归档根目录 |
| 元数据（设备、任务、索引、规则、标签） | 本地 SQLite 数据库，结构公开见 [DATABASE_SCHEMA.md](../DATABASE_SCHEMA.md) |
| 设备私钥 | 本地文件，权限 0600，**永不入库、不入日志、不离开设备** |

**卸载 AA4C 不会带走你的任何数据。** 详见 [《开源 · 开放 · 安全》](OPEN_AND_SECURE.md)。
