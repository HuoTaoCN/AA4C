# 开源 · 开放 · 安全

> [English](en/OPEN_AND_SECURE.md) · [返回首页](../README.md)

这份文档讲清楚三件事：AA4C 的开源承诺是什么、"开放"具体开放在哪、你的数据到底去了哪里。

**每一条都可以在仓库里逐条核对**——这是我们把它们写下来的意义。写"我们尊重你的隐私"没有价值，能被验证的陈述才有价值。

## 一、开源

### 许可证：Apache License 2.0

选 Apache-2.0 而不是 GPL，是为了让这个项目**能被真正用起来**：

- 允许商业使用、允许企业内部集成、允许闭源分发衍生品
- **附带专利授权**——贡献者不能反过来用专利起诉使用者
- 与绝大多数生态兼容

### 开源的范围

不是"开放部分源码"，是全部：

| 内容 | 位置 |
|------|------|
| 全部应用代码 | `crates/`（Rust 核心）、`apps/desktop/`（Tauri + Vue 前端） |
| 服务器代码 | `crates/aa4c-server/`（信令 + 中继） |
| 构建与发布流水线 | `.github/workflows/`（CI、release、引擎打包） |
| 引擎获取脚本 | `scripts/fetch-engines.sh`（带校验和） |
| 全部设计文档 | 仓库根目录的架构 / 协议 / 数据库 / 各模块设计文档 |
| 测试 | 各 crate 的 `src/` 内联测试与 `tests/` 集成测试 |

**没有"社区版 / 专业版"之分，没有闭源的服务端组件。**

### 构建是公开且可复现的

每个发布版本由 GitHub Actions 在 Windows / macOS / Linux 三平台公开构建，流水线配置在仓库里，日志任何人可见。你也可以完全不信任我们提供的安装包，自己 `cargo build` + `pnpm tauri build`——步骤就在 [README](../README.md#从源码构建) 里。

### 依赖治理

- 依赖只用 **MIT / Apache-2.0 / BSD** 等宽松协议
- 引入新依赖前检查其安全公告史，CI 中运行 `cargo audit`
- 项目一贯克制：能手写几十行搞定的事不引入新依赖（例如 GGUF 头解析、文件魔数识别都是手写的）

### GPL 组件的隔离（为什么这很重要）

AA4C 用到三个外部引擎：

| 引擎 | 用途 | 许可证 |
|------|------|--------|
| aria2 | HTTP / HTTPS / FTP 下载 | GPL-2.0 |
| Transmission | BT / 磁力下载 | GPL-2.0 |
| llama.cpp (`llama-server`) | 本地 AI 推理 | MIT |

对于两个 GPL 引擎，AA4C 的做法是：

- ❌ **不复制它们的源码**进仓库
- ❌ **不链接它们的库**
- ✅ 作为**独立子进程**运行，只通过 **127.0.0.1 回环 + RPC** 通信

这不是钻空子，是干净的进程边界。它带来两个实际好处：**AA4C 自身能保持 Apache-2.0**（企业可以放心集成），以及**引擎可以随时替换**（BT 引擎就从 qBittorrent 换成过 Transmission，上层代码几乎不受影响）。

贡献者也受同一条规则约束：[CONTRIBUTING.md](../CONTRIBUTING.md) 明令禁止把 GPL / AGPL 代码复制进仓库。

## 二、开放

开源只是"代码能看"。**开放**是"你能走、能改、能自己接管"。

### 1. 协议开放

线路协议、帧格式、握手流程、配对状态机、同步索引交换、分享链接格式——全部写在 [PROTOCOL.md](../PROTOCOL.md) 里，包含版本协商与兼容规则。

**任何人都可以照着实现一个兼容客户端**，不需要我们授权，也不需要通过什么认证。

### 2. 数据开放：你随时可以走

这是最实际的一条。AA4C **没有任何形式的数据锁定**：

| 数据 | 形态 |
|------|------|
| 收到 / 下载 / 归档的文件 | **就是普通文件**，放在你指定的普通目录里。没有专有容器、没有加密封装、没有分块黑盒 |
| 元数据（设备、任务、索引、规则、标签） | 本地 SQLite 数据库，表结构公开在 [DATABASE_SCHEMA.md](../DATABASE_SCHEMA.md)，任何 SQLite 工具都能打开 |
| 配置 | 同一个本地数据库里的键值 |

**卸载 AA4C 不会带走你的任何数据**，也不需要什么"导出向导"——文件本来就在那里，用文件管理器直接拿走即可。

### 3. 基础设施开放：只允许自建

跨网络连接需要的信令与中继服务器，AA4C **不提供官方公共节点**，只支持你自己部署（[自建服务器指南](SELF_HOSTING.md)）。

这看起来是"少给了一个便利功能"，但它换来的是：

- 不存在"官方服务器关停 / 欠费 / 被封"导致你的设备连不上
- 不存在"运营方哪天被要求交出数据"
- 你能看到它跑在哪台机器上、开了什么端口、留了什么日志

### 4. 面向扩展

分层架构里的 Plugin API（Download / Sync / Share / AI / Storage / Notification）与开放 API 是 V1.0 的既定目标，见 [ARCHITECTURE.md](../ARCHITECTURE.md) 与 [ROADMAP.md](../ROADMAP.md)。

## 三、安全

完整威胁模型与漏洞报告流程见 [SECURITY.md](../SECURITY.md)，这里是要点。

### 设计原则

**1. 加密不可关闭。** 项目规则明令禁止引入"关闭加密 / 关闭校验"的配置项。没有"为了速度关掉 TLS"这种选项。

**2. 默认最小权限。** 配对默认落在「朋友」级别，不参与文件索引；接收文件默认需要确认；远程连接默认关闭；归档规则默认全部停用。所有危险能力都要你**明确打开**。

**3. 自动化必须可逆。** 自动归档移动过的文件，一键撤销。

**4. AI 不掌握文件操作权。** 只有确定性规则能自动移动文件，AI 的输出永远只进"待确认"队列。

### 机制一览

| 层 | 机制 |
|----|------|
| 设备身份 | Ed25519 密钥对；DeviceId = BLAKE3(公钥)，无法伪造 |
| 信任建立 | 双向 6 位 PIN 目视确认。**PIN 由两端各自独立算出，从不经过网络**——中间人无法让两边显示一致 |
| 通道加密 | TLS 1.3 + 自签证书 + **证书固定**（指纹即 DeviceId），不依赖任何 CA，因此不受 CA 体系被攻破影响 |
| 数据完整性 | 文件级 BLAKE3 哈希校验，不一致自动重传 |
| 路径安全 | 接收端强制净化相对路径，拒绝 `..` 与绝对路径（防路径穿越写文件） |
| 协议健壮性 | 帧长上限 16 MiB，非法帧立即断开（防协议层 DoS） |
| 授权 | 只有已配对设备可发起传输；四级信任分级控制索引与同步范围 |
| 密钥保管 | 私钥仅存本地文件（权限 0600），**永不入库、永不入日志、永不离开设备** |
| 本地引擎 | aria2 / Transmission / llama-server 一律绑定 `127.0.0.1` + **每次启动重新生成的随机密钥**，局域网上的其他机器连不到 |
| 子进程管理 | 直链引擎异常退出后自动重连并重新拉起；主程序退出时有孤儿进程防护，不留后台残留 |

### 防护范围

**在范围内**：局域网窃听、中间人攻击、伪造设备身份、路径穿越、未配对设备发起传输、传输内容篡改、协议层 DoS、中继服务器窥探内容（端到端加密，中继只见密文）。

**明确不在范围内**：设备本身被攻破（恶意软件 / 已 root）、用户跳过 PIN 核对主动配对了攻击者、流量分析（能看出"两台设备在传东西"和流量大小，但拿不到内容）、物理接触已解锁的设备。

把不做的事写清楚，和把做到的事写清楚同样重要。

### 给贡献者的硬性规则

- 涉及密钥、TLS 校验、路径处理的改动，PR **必须包含正反两向测试**（合法通过 / 非法拒绝）
- 禁止在日志中输出私钥、完整公钥、文件内容
- 不得引入关闭安全特性的配置项

### 漏洞报告

**请不要为安全漏洞开公开 Issue。** 通过 [GitHub Security Advisory](https://github.com/HuoTaoCN/AA4C/security/advisories/new) 或 security@aa4c.com 私下报告。承诺：72 小时内确认收到，7 天内初步评估，目标 90 天内修复披露，修复后公开致谢（除非你希望匿名）。

## 四、隐私：你的数据去了哪里

### 一句话：哪儿也没去。

| 常见担心 | AA4C 的实际情况 |
|----------|-----------------|
| 会不会上传我的文件？ | **不会。** 局域网内设备直连；跨网络时经过的也只有你自己部署的服务器，且是端到端加密的密文 |
| 会不会收集使用数据？ | **不会。** 没有遥测、没有崩溃上报、没有"匿名使用统计"。代码里没有任何分析 SDK |
| 会不会读我的文件内容做分析？ | **不会。** AI 完全在本机运行，模型是你自己的文件，零云端调用 |
| 需要注册账号吗？ | **不需要。** 没有账号体系，没有登录，没有云端身份 |
| 不用的时候会偷偷联网吗？ | **不会。** 远程连接开关默认关闭，关着时 AA4C 只在局域网活动 |
| 有没有内置广告 / 推广 / 资源推荐？ | **没有。** 下载中心不提供、不索引、不推荐任何资源 |
| 卸载后数据还在吗？ | **在。** 都是普通文件，放在你指定的目录里 |

### 唯一会主动出网的情况

只有一种：**你自己填了服务器地址并打开了「开启远程连接」**。这时 AA4C 会连接**你自己部署的那台**服务器，用来注册端点和查询对方地址。除此之外没有任何出站连接。

**没有更新检查、没有配置拉取、没有 tracker 列表自动同步**——最后这一条是刻意的取舍：同类软件常从 GitHub 定时同步公共 tracker 列表，那等于应用自己定期往第三方地址发请求，与"不配置就完全不出网"冲突，所以 AA4C 只做手动填。

### 自建服务器能看到什么

即使你开了远程连接，服务器的可见范围也被限制到最小：

- **能看到**：设备 ID、它当前的网络端点、每台设备上传的允许查询名单、中继流量大小
- **看不到**：文件内容、文件名、目录结构、任何文件元数据

中继是**纯管道**，只盲转发端到端加密的字节流，不解密也不理解传输协议。

## 五、我们明确不做的事

边界和功能同样是产品的一部分：

| 不做 | 原因 |
|------|------|
| 社区 / 内容平台 | 内容审核、举报处理、法律风险、运营成本极高，且不是这个项目要解决的问题 |
| 资源广场 / 模型广场 / 文件社区 | 不做中心化内容分发 |
| 中心化云盘 / 网盘 | 坚持用户数据属于用户自己，不建集中存储 |
| 官方公益中继节点 | 基础设施只允许自建，避免单点与数据风险 |
| 遥测与使用统计 | 哪怕匿名 |
| 账号体系 | 设备身份就是身份，不需要中心化账户 |
| 关闭加密的开关 | 安全特性不可配置关闭 |
| 让 AI 直接操作文件 | AI 只能建议，用户确认才生效 |

## 六、怎么自己验证

不用相信上面任何一句话，都可以自己查。

**查有没有遥测 / 第三方端点**：

```bash
grep -rniE "analytics|telemetry|sentry|amplitude|mixpanel|posthog" crates apps/desktop/src
grep -rnoE "https?://[a-z0-9.-]+" crates/*/src/*.rs
```

**查引擎是不是只绑回环**：

```bash
grep -rn "rpc-bind-address\|LLAMA_ARG_HOST" crates/
```

**查网络出站行为**：读 `crates/aa4c-core/src/server_link.rs`——这是 AA4C **自己**发起的唯一一类出站连接（连你配置的服务器），且受 `enable_remote` 开关控制。除此之外的出站流量都是你**主动要求**的结果：发给某台设备的文件、你粘贴的下载链接。

**查加密与身份**：读 `crates/aa4c-identity/`（Ed25519 密钥、TLS 证书固定、PIN 推导），配套测试覆盖了"指纹匹配通过 / 不匹配拒绝"两个方向。

**查数据存了什么**：`DATABASE_SCHEMA.md` 是表结构文档，也可以直接用 SQLite 工具打开本地数据库看。

**自己构建一份**：

```bash
cargo test --workspace
cd apps/desktop && pnpm install && pnpm test && pnpm tauri build
```
